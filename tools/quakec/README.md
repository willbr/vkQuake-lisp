# QuakeC references for the Lisp compiler

The aim of this fork is to compile a Scheme-style Lisp to **stock Quake's
original NetQuake VM**. Generated `progs.dat` files must work with the unmodified
engine. Version 6 bytecode, the stock ABI, and stock builtin numbers are the
baseline. Engine extensions, extra opcodes, and new C builtins are excluded from
the baseline. Any Lisp runtime must be compiled into ordinary bytecode.

## Setup

From the repository root:

```sh
./tools/quakec/setup.sh
```

Requires Git, a C compiler, Make, Python 3, and zlib headers/library (provided by
the macOS Command Line Tools; on Debian/Ubuntu install `zlib1g-dev`). The script
fetches exact Git commits, builds FTEQCC, and compiles the original gameplay code
with `-Tq1 -O0 -Fwasm`: Quake 1 bytecode, no optimizations, and an assembly dump.
It also builds a command-line host around id Software's original, unmodified
`WinQuake/pr_exec.c`. Static checks cover the generated file's format, ABI layout,
signed global operands, branch targets, function frames, and builtin numbers.
The old gameplay source produces upstream warnings; see `build/quakec/compile.log`.

| Location | Contents |
| --- | --- |
| `third_party/quake-tools/qcc/v101qc/` | Original single-player QuakeC source, version 1.01 |
| `third_party/quake-tools/qcc/` | Original id Software compiler, including parser, code generator, and language notes in `qcc.h` |
| `third_party/fteqw/engine/qclib/` | Modern FTEQCC compiler source |
| `third_party/quake/WinQuake/` | Original NetQuake interpreter, ABI, and builtin definitions |
| `build/quakec/bin/fteqcc` | Built native command-line compiler |
| `build/quakec/bin/stock-vm` | CLI host using the original interpreter |
| `build/quakec/reference/progs.dat` | Compiled reference gameplay |
| `build/quakec/reference/progs/qc.asm` | Assembly listing for comparison with Lisp output |

Upstream repositories:

- [id-Software/Quake-Tools](https://github.com/id-Software/Quake-Tools), pinned to
  `c0d1b91c74eb654365ac7755bc837e497caaca73`.
- [fte-team/fteqw](https://github.com/fte-team/fteqw), pinned to
  `f09ac7cccd2d713ddf881d3f1324703082c2cfe4`.
- [id-Software/Quake](https://github.com/id-Software/Quake), pinned to
  `bf4ac424ce754894ac8f1dae6a3981954bc9852d`.

The fetched repositories are ignored by Git; their pinned revisions live in
`setup.sh`. Keep their upstream license files with the sources. All generated
files and working source copies live under `build/quakec/`.

To recompile experiments, edit the working copy under
`build/quakec/reference/progs/` and run:

```sh
cd build/quakec/reference/progs
../../bin/fteqcc -Tq1 -O0 -Fwasm
```

Running setup again refreshes the working copies from upstream. Put permanent
experiments outside `build/`.

## CLI development loop

Build the toolchain, compile the test programs, and exercise the original VM:

```sh
./tools/quakec/setup.sh
python3 -m unittest discover -s tools/quakec/tests -v
./tools/quakec/run-stock.sh build/quakec/stock-tests/progs.dat stock_smoke
./tools/quakec/run-stock.sh build/quakec/stock-tests/progs.dat stock_twice 21
```

Both examples return `42`. The CLI prints a scalar float result and interpreted
instruction count, and returns a nonzero status on errors. Arguments currently
support scalar floats. Use `--list` instead of a function name to list entries.
The wrapper runs static checks before invoking the interpreter; it is the
supported entry point for generated bytecode.

This is an interpreter test host, not a complete Quake server. It has no maps,
physics, networking, or rendering. Builtins #25 (`dprint`, always printed) and
#10 (`error`, a nonzero exit with the diagnostic) are provided; calling other
engine builtins fails explicitly. The host has
simplified entity storage and currently runs on little-endian machines. The
interpreter source and its stack/watchdog limits are unchanged. Host setup code
is in `stock-vm/`; the copied upstream interpreter remains under `build/`.

The tests cover arithmetic, vectors, branches, calls, output, CLI arguments,
stock stack overflow and runaway-loop failures, and rejection of incompatible
programs. They require no purchased game data. Full gameplay, entity behavior,
and save/load compatibility still need testing in an unmodified Quake engine.

## Run the reference game

Use an isolated data root with links to your purchased game data and the compiled
reference mod. For the GOG extraction used in this workspace:

```sh
mkdir -p build/quakec/run
ln -s "$HOME/Games/Quake-gog/app/id1" build/quakec/run/id1
ln -s ../reference build/quakec/run/qc-reference
./build/vkquake -basedir "$PWD/build/quakec/run" -game qc-reference
```

Create the links once. The reference is older gameplay code than the GOG
installation; its loose `progs.dat` overrides the compiled code in `id1` while
reusing the purchased maps, models, sounds, and music.

For an additional headless integration check after building vkQuake:

```sh
./build/vkquake -dedicated -noudp6 -port 0 \
  -basedir "$PWD/build/quakec/run" -game qc-reference \
  +listen 0 +developer 1 +map start +wait +quit
```

Successful output includes `Server spawned.`. This checks that the engine can
load the reference bytecode and execute the map's spawn functions. Passing this
vkQuake check alone does not establish stock-engine compatibility. The
[Lisp map boot smoke test](../../qslisp/README.md#boot-a-map-in-stock-quake)
runs the generated `progs.dat` in the original DOS Quake executable.

## Headless map editing

```sh
python3 tools/quakec/map_editor.py examples/annex.map inspect
python3 tools/quakec/map_editor.py examples/annex.map preview build/annex-side.svg --view side
python3 tools/quakec/map_editor.py examples/annex.map build build/annex.bsp
```

Install `pyglet>=2.1,<2.2` in your Python environment to open the native 3D viewer.

```sh
python3 tools/quakec/map_editor.py examples/uplink.map view3d --port 8765
```

Drag to orbit, right-drag or Shift-drag to pan, and scroll to zoom. Use the two
height sliders to cut through stacked decks. Click an entity marker for its map
index and coordinates. The viewer reloads the map after it is saved.

`--port` is optional and starts the existing editor API on localhost. Use
`GET /view` to read the shared camera, `POST /view` to update it, and
`GET /view.png` to capture the window. The JSON fields are `target` in map units,
`yaw` and `pitch` in degrees, `span` for the vertical view size in map units,
`slice` as two Z coordinates or `null` for the full height, and `entities`
as a boolean. Send the fields you want to change.

```sh
curl -H 'Content-Type: application/json' -d '{"target":[-3480,-2110,54],"span":1150,"slice":[-35,175]}' \
  http://127.0.0.1:8765/view
```

The editor preserves untouched map source. Use `apply edits.json` to preview an
edit as a diff, and add `--write` to save it. The file is a JSON array of
operations. Operation names include `box`, `ramp`, `bank`, `switchback`,
`place`, `set`, `link`, and `translate-brush`. Entity and brush indices
come from the map order, starting at zero.

For a persistent session, run `serve --port 8765` on a map. Read `GET /` for
the current revision and entity indices. Send `POST /edit` with that
`revision`, an `operations` array, and optional `write: true`. An intervening
edit invalidates the old revision. `GET /preview?view=side` returns an SVG.

## Model editing

Open a recipe in the native Pyglet editor with the same orbit, pan, and zoom
controls as the map viewer. Supply a local Quake PAK or `palette.lmp` to preview
the actual palette colors.

```sh
python3 tools/quakec/model_editor.py examples/models/upbuddy.json build/upbuddy.mdl \
  --view --palette "$HOME/Games/Quake-gog/app/id1/pak0.pak" --port 8766
```

Click a part in the model or parts list. In **Base mesh**, move a part, resize a
box, or add another box. Select a named pose to edit that pose's part offset,
use **Rotate** to edit joint angles, or duplicate it with **+ Pose**. Choose a
clip and press **Play** or Space to preview it. Click a coordinate to type an exact value.
Click a palette swatch to assign it. **Save recipe** updates the JSON source,
and **Export MDL** writes the current draft to the output path. The four Uplink
models use the recipes in [examples/models](../../examples/models).

With `--port`, `GET /view` reports the camera, part, and pose, and `GET /view.png`
captures the window. `POST /view` accepts `target`, `yaw`, `pitch`, `span`,
`part`, `pose` (`null` for the base mesh), `position` (the part position or
pose offset), `clip`, and `playing`. Position changes edit the current draft.

`python3 tools/quakec/model_editor.py recipe.json build/model.mdl` writes a
stock version 6 alias model. A recipe has a `palette` of up to eight Quake
palette indices and named `parts`. A part can have `low` and `high` box corners,
convex `faces` with `points`, or tapered `rings` with `[height, radius_x, radius_y]`
sections, `origin`, and `sides`. A part or face's `material` selects a palette
entry, starting at zero. Named `frames` map parts to an offset or an object
with `offset` and `rotate`. Rotations are XYZ Euler angles in degrees around
the part's `pivot`, with its center or ring origin as the default.
`animations` lists ordered `frames` and `fps` for each stock MDL frame group.
The buddy's groups are idle, walk, and assist in that order.
[Uplink asset build](build-uplink-assets.py)

## Procedural textures

Open the native Python editor with the same Pyglet installation used by the
model viewer. The editor looks for `id1/pak0.pak` and the setup's linked game
data at `build/quakec/run/id1/pak0.pak`. Use `--palette` to point it at a
different copy of Quake's `pak0.pak` or `gfx/palette.lmp`.

```sh
python3 tools/quakec/texture_editor.py --port 8767
```

Use **Pipeline** to add sources such as value, fractal, cellular, and white
noise, or solid values, bands, and grids. Each source has editable parameters,
a blend mode, and an amount. Add filters for blur, sharpen, emboss, threshold,
or invert. The stages run from top to bottom. Select a stage to edit it, move
it up or down, or remove it. Click a number to enter an exact value.

Use **Texture** to set the name, dimensions, and seed. Use **Palette** to select
a stock ramp or choose individual Quake palette indices in the order that
values should map to them. The 3 × 3 preview shows how the texture tiles, and
the thumbnails switch between four mip levels. Noise and filters wrap across
the tile edges. The pipeline maps the processed values to palette indices
after the last stage.

Use **Export WAD2, PNG, and recipe** to write all three files under
`build/textures`, or set `--output-dir` to choose another destination. Pass
the saved JSON as a positional argument to reopen it. Add `--export` to rebuild
the files from a recipe without opening the window. The original material
preset recipes can be exported using the original editor at commit `7be02052`.

With `--port`, the editor listens on `127.0.0.1` while the window is open.
`GET /` lists available settings. `GET /view` reads the current recipe and
preview settings, and `POST /view` updates them. Send any of `recipe` (a patch
to the current recipe), `tiles` (1 or 3), `mip` (0 through 3), or `tab`
(`pipeline`, `texture`, or `palette`). When present, `recipe.stages` replaces
the ordered list. Each stage takes a `kind`, optional `params` and `amount`
from 0 to 100, and an optional `blend` for sources. `recipe.colors` sets the
ordered indices for a custom ramp. An empty list uses the named `recipe.ramp`.
`GET /view.png` captures the window. `GET /texture.png`, `GET /texture.wad`,
and `GET /recipe.json` download the current draft.

```sh
curl -fsS -H 'Content-Type: application/json' \
  -d '{
    "recipe": {"name":"relay_wall","ramp":"sandstone","seed":42,"stages":[
      {"kind":"grid","params":{"columns":4,"rows":8}},
      {"kind":"fractal","blend":"add","amount":50},
      {"kind":"emboss","amount":25}
    ]},
    "tiles":3
  }' \
  http://127.0.0.1:8767/view
curl -fsS --create-dirs http://127.0.0.1:8767/texture.wad -o build/textures/relay_wall.wad
python3 tools/quakec/map_editor.py examples/signal.map build build/signal-stone.bsp \
  --wad build/textures/relay_wall.wad
```

For maps that use `signal.wad`, each `--wad` adds textures to the stock build's
WAD. A matching texture name replaces the earlier entry, as `relay_wall` does
in the example. Use the exported texture name on map faces.

The Uplink map uses generated wall and floor textures for its seven decks and
the lift tread. Its [editable recipes](../../examples/textures/uplink) and
[WAD2](../../examples/textures/uplink.wad) are checked in. The map build
automatically embeds the textures it uses. Run the two commands below after
editing a recipe to refresh the WAD and BSP.

```sh
python3 tools/quakec/build-uplink-textures.py
python3 tools/quakec/map_editor.py examples/uplink.map build build/uplink.bsp
```

## VM listings and fixtures

```sh
python3 -m qslisp examples/square.scm -o build/progs.dat --symbols
python3 -m qslisp.vm_tools disassemble build/progs.dat --symbols build/progs.sym --function square
python3 -m qslisp.vm_tools assemble fixture.qca -o build/fixture.dat
```

The optional JSON sidecar records the file digest and source locations for
half-open statement ranges. Listings work from the bytecode alone.

A fixture can declare `.float name value`, `.builtin name number arity`, or
`.function name locals [parameter-width ...]`. Each function ends with
`.end`. Write stock opcode names with operands separated by spaces. Use
`%offset` for local slots, `[index]` for raw globals, and `label:` for relative
branches. The assembler statically validates the resulting file.
[Stock VM fixture](../../qslisp/tests/test_vm_tools.py)

## VM target

The pinned original engine is authoritative for the compiler target:

- [`WinQuake/pr_comp.h`](../../third_party/quake/WinQuake/pr_comp.h): bytecode
  format and operand types.
- [`WinQuake/pr_exec.c`](../../third_party/quake/WinQuake/pr_exec.c): original
  instruction execution, signed global addressing, stack and instruction limits.
- [`WinQuake/progdefs.q1`](../../third_party/quake/WinQuake/progdefs.q1): required
  global/entity-field ABI, CRC `5927`.
- [`WinQuake/pr_cmds.c`](../../third_party/quake/WinQuake/pr_cmds.c): stock
  builtin table. Reserved `PF_Fixme` entries are unavailable.
- [`WinQuake/quakedef.h`](../../third_party/quake/WinQuake/quakedef.h): original
  engine limits, including 600 entities.

| Constraint | Stock baseline |
| --- | --- |
| Program format | Little-endian version 6; stock global/field layout and CRC `5927` |
| Instructions | Opcodes 0–65; no VM extensions |
| Global operands | Nonnegative signed 16-bit slot addresses, 0–32,767 |
| Storage bank | At most 32,768 32-bit slots shared by globals, locals, constants, temporaries, and any global-backed Lisp heap |
| Branches | Signed 16-bit relative offsets |
| Calls | Up to eight arguments, at most three slots each; three return slots |
| Active call depth | Fewer than 32 bytecode frames; entry at depth 32 fails |
| Saved locals | 2,048 slots shared across active frames |
| Watchdog | A VM entry fails when its instruction counter reaches 100,000 |
| Entities | 600 total, shared with gameplay |

The static checker validates formats and individual frames. It cannot prove
total recursion depth, combined saved-locals use, runtime handle correctness,
watchdog compliance, or peak entity use. These need execution tests and compiler
runtime policies. The original qcc tool's own smaller array limits are distinct
from interpreter limits.

Useful corresponding files in the development engine are:

- [`Quake/pr_comp.h`](../../Quake/pr_comp.h): version 6 file layout, opcodes,
  global slot conventions, statements, definitions, and function records.
- [`Quake/progdefs.q1`](../../Quake/progdefs.q1): engine-visible globals and
  entity fields, with ABI CRC `5927`.
- [`Quake/pr_exec.c`](../../Quake/pr_exec.c): instruction execution and function
  calls, including saving/restoring function locals.
- [`Quake/pr_edict.c`](../../Quake/pr_edict.c): program loading and ABI checks.
- [`Quake/pr_cmds.c`](../../Quake/pr_cmds.c): engine builtins callable from game code.

For the direct Lisp backend, emit little-endian `progs.dat` version 6. Statements
are eight bytes: a 16-bit opcode and three 16-bit operands. Globals use 32-bit
slots; vectors span three slots. Return values occupy slots 1–3; up to eight
arguments use three slots each starting at slot 4. Builtins are functions with
negative `first_statement` values. Most operands address globals; branches use
signed relative statement offsets.

Running game code also requires the engine's global/field layout and expected
entry functions; setting CRC `5927` alone does not provide that layout. Preserve
the declarations before `end_sys_globals` and `end_sys_fields` in `defs.qc` when
building a compatible program. The original source shows the gameplay entry
functions such as `worldspawn`, `StartFrame`, and `ClientConnect`.

The first [compiler milestone](../../qslisp/README.md) implements CLI execution
of arithmetic, conditionals, lexically scoped variables, and named functions.
It emits bytecode directly; FTEQCC provides reference output. The map boot
example exercises `worldspawn`, model precaching, and `StartFrame` in stock Quake.
The [Signal Room verification](../../qslisp/README.md#play-and-verify-the-signal-room)
also drives a local client through walking, jumping, firing, and resetting and
samples the original engine's instruction counters.

The [pair arena](../../qslisp/README.md#pair-arena) uses fixed global storage,
checked accessor trees, and bump allocation released at the end of each engine
entry. It is compiled into ordinary bytecode,
with repeatable size and instruction measurements. Escaping closures and other
heap types must extend this runtime. Do not introduce a C-managed heap or depend
on engine string-buffer, allocation, or reflection extensions. Macros can run
in the host compiler.
The compiler emits self tail calls as loops and other named tail calls through
requests resolved at the call site, while preserving the stock frame and watchdog limits.
Full Scheme conformance, closures, global values, and stock save/load integration
remain future work. Heap capacities are configurable and subject to stock limits.
